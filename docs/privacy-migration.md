# Privacy and local migration

Open Settings, then Privacy and migration. Enter absolute project, directory or file paths, one per line. Rules also accept paths to uploaded originals. Exclusions never grant access to a new source directory. Resume setup to change source roots.

New imports filter source messages before compaction. Each summarization/refinement attempt rechecks the policy; changing rules during a job stops further requests and prevents publication. Refinement reconstructs context from wholly permitted summaries. Mixed-source records are withheld conservatively. Chat withholds excluded sourced knowledge and, while exclusions exist, unsourced vault notes, scores and digests. Text typed directly into chat is sent to your configured model; do not paste sensitive content you intend to exclude.

Previously imported knowledge, source metadata, diagnostics and backups stay local and are not erased by exclusion. They remain available for local inspection; some source viewers deny excluded originals. Remove retained local files separately if required. Removing a rule permits future processing again. Existing provider-side data cannot be recalled by SelfOS. Redaction is best effort, not a guarantee that sensitive content has been removed. Settings displays the configured provider, endpoint and model; providers and proxies may retain transmitted data under their own policies.

## Format

The downloaded UTF-8 JSON has `format: selfos-portable`, `version: 1`, `origin_vault`, `origin_platform`, `includes`, `files` and `settings`. `files` maps allowlisted vault-relative paths to Base64 bytes. Canonical files include `.knowledge_pipeline.json`, `.knowledge_corrections.json`, `.knowledge_settings.json`, `.knowledge_sources.json` and optional `.knowledge_migration.json`. State preserves records, source IDs, original provenance, cached summaries and source/project identity links. Relevant destination settings are provider, model, base URL and proxy mode/URL. API keys, environment files, account databases, sessions, diagnostics and onboarding allowances are excluded. Sensitive information can still appear in knowledge or source text; protect the export. Maximum decoded content is 64 MiB; file sizes are checked before allocating export reads.

Original harness files are never bundled. Uploaded originals under `.knowledge_uploads/originals/` and knowledge backups under `.knowledge_backups/` are omitted unless explicitly selected. Backups can contain old knowledge that is no longer current. These options are off by default.

Import a JSON export through the same panel into a destination without canonical knowledge files. Import does not merge or overwrite existing knowledge and makes no model requests. Credentials remain empty in imported model settings. Re-enter a key locally when needed. Source roots and exclusion rules retain their original absolute paths: inspect them after moving machines and add the new source roots and corresponding exclusions before importing more data. Included uploaded source paths are rebased to the destination vault; the original path is saved as `migration_original_path`. Historical provenance is preserved. External source paths remain unchanged and every source is reported as resolved or unresolved. A resolved file path does not prove unchanged content; normal source-view hash checks still apply. Generated markdown views are recreated on the next knowledge operation; the knowledge browser reads imported canonical state directly.

Imports containing model settings reject an existing destination model configuration instead of erasing its key. Model configuration writes participate in failure rollback together with imported knowledge. Record structures and correction ledgers are validated before writing.

Windows and POSIX source paths use the export's origin-platform semantics. Foreign source roots and exclusions are preserved as unresolved metadata in `.knowledge_migration.json`; active local roots remain empty until configured on the destination. Included uploaded originals and their privacy exclusions are rebased to the new vault. External harness paths remain unresolved rather than being interpreted as relative paths on the new operating system.
