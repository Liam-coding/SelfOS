# Shared internationalization implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task by task.

**Goal:** Implement #7 with one keyed localization mechanism covering current UI, English default/fallback, Simplified Chinese, parameterized messages and locale-aware formatting without disrupting user state.

**Base/dependency:** 55080ac, main after PR #45 and PR #44 merged. This feature uses their packaged resource layout and preserves search, source pagination, publication status and project timelines.

**Architecture:** Package locale metadata and namespace JSON files feed a shared Python catalog and a single browser runtime. Server templates render English initially; the browser resolves persisted locale preferences, updates keyed text/attributes/dynamic bindings and formats dates/numbers with Intl. Existing global entry points, API/auth and SSE contracts stay intact. Features no longer choose between inline Chinese/English message pairs.

**Tech stack:** Existing Python, packaged JSON, HTML/CSS/JavaScript and Intl. No additional runtime dependency or model/source import.

**Spec:** https://github.com/Liam-coding/SelfOS/issues/7

## Constraints and decisions

- Preserve user knowledge, source files, model/auth configuration, checkpoints and five frozen acceptance files. Use synthetic fixtures, never real model calls or a full production import.
- Locale metadata supplies canonical IDs, aliases, display names and document/Intl tags. Discover supported locales from package resources; unknown preferences resolve to English. Accept legacy zh preferences through metadata. Adding a locale requires resources, not feature-specific conditions.
- English is the authoritative key/parameter contract and fallback. Validate key sets, placeholder sets, string types and duplicate locale aliases. User-authored record/source content is never translated or interpreted as a key.
- Use explicit keys for navigation, dialogs, settings, placeholders, title/aria labels and dynamic statuses/errors. Static markup uses data-i18n attributes; browser dynamic text uses t/bindText with parameters. Locale and server data use safe text/attribute rendering, never HTML evaluation.
- Bindings retain message key/parameters so a language switch updates pending/success/error status immediately. Do not reset form values, call model/source APIs, start imports or cancel tasks on a language event. Already opened source text remains intact.
- Keep date-only values date-only and unknown/ambiguous legacy dates unknown. Use Intl for explicitly recorded dates/timestamps, counts and numbers; parameter interpolation must not invent time or knowledge.
- Auth and errors use stable error codes and English fallback. Unsupported backend/provider messages get a localized generic error; preserve relevant HTTP status for session-expiry handling. Raw conversation/progress diagnostics remain original content, distinct from localized UI status.
- Cached dashboards need shared-runtime injection and current component/script replacement on authenticated reads without writing their file, scanning sources or recomputing knowledge. Central legacy attribute compatibility may translate older saved markup; current maintained templates/scripts contain no scattered bilingual pairs.
- The #30 byte snapshot describes the intentionally unchanged refactor baseline, not the intended UI changes in this feature. Replace its active byte-equality assertion with localization/rendering assertions while keeping the original fixture as historical evidence. Never alter the five frozen knowledge fixtures.

## Review focus

- Legacy zh/unsupported preferences, partial new locales, duplicate aliases and malformed catalogs.
- HTML/script-looking parameters, missing placeholders and fallback consistency between Python/browser.
- Language switching during a model test/save, import/SSE, source read or open dialog; preserve values, focus and active operation.
- Cached pre-i18n pages, global initialization order and auth fetch wrapping; avoid duplicate runtimes/listeners or any public data exposure.
- Dynamic empty/error/count states, dates with and without timezone, accessible labels and supported locale selectors.
