# OpenCode Ingestion Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans task-by-task; observe RED and GREEN for each deliverable, and request one fresh whole-branch review at the end.

**Goal:** Deliver the approved OpenCode reference adapter: explicit native discovery, read-only bounded scanning, immutable export ingestion, resumable organization and verified original navigation. Keep #12 open for the unidentified DeepSeek Harness.
**Architecture:** Adapter-owned normalization and locators feed the existing compaction/classification/transaction pipeline. Typed selection separates database storage permissions from project exclusions. SelfOS-owned checkpoints preserve sealed and unsealed parts across bounded native scan pages.
**Tech Stack:** Python 3.10+, standard-library SQLite/JSON/filesystem, packaged browser scripts/locales, pytest and isolated Chromium.
**Spec:** docs/superpowers/specs/2026-11-13-opencode-ingestion-design.md (user approved; historical pending-approval wording is not a new permission gate).
**Base:** 93efb67, the tested #11 implementation in PR73; implementation PR will initially be stacked on feat/document-upload. The OpenCode design commit is copied separately; PR71 remains documentation-only.

## Global Constraints
- Verified profile: anomalyco/opencode v1.19.5, commit 810c0eba1a7348036f8bdf61e6632d0c36c6876c; required session/message/part projection only. Unknown/V2-only formats are explicit unsupported status.
- Synthetic SQLite/exports only; no private conversations, upstream execution, paid providers, or physical Mac claims.
- Native roles retain content_identity provenance; exports remain quoted_dialogue even for user roles. Stable logical identities include native linkage, project/time/role/provenance and meaningful text digest; paths are locator metadata only. At most eight identical-copy locators.
- Preserve version-1 source roots/exclusions without broadening. Database permissions select exact files; excluded project session bodies are never read. Recheck every candidate locator at dispatch/refinement/publication/viewing.
- SQLite URI mode=ro, query_only, no immutable live-WAL shortcut, disabled extensions, trusted_schema disabled when supported; never migrate/checkpoint upstream storage.
- Builder defaults: 250 ms busy timeout, 10 s scan deadline, 100 sessions and 2,000 messages per bounded scan, 100 messages per page, 256 parts per message, 64 KiB message-info JSON, 256 KiB part JSON, 256 KiB normalized message, 8 MiB returned text per scan. Oversize records are skipped with diagnostics, never silently truncated.
- SelfOS staging: at most 64 MiB per snapshot and 128 MiB aggregate, 8 MiB in-memory page/checkpoint payload. Cursor advances only with an atomic page/input save. Stable compaction ordinals and high-water marks; changed consumed prefixes require explicit restart. New rows beyond high-water belong to a later scan.
- Exports use #11 immutable admission, UTF-8 up to 20 MiB, strict expected shape and bounded counts; unknown JSON is rejected. No automatic extra model classification stage. Existing corrections, cache, usage, backups, migration and stop remain authoritative.

## Review Focus
- Live WAL changes after a scan: preserve snapshot high-water and diagnose changed consumed evidence before resuming or publishing (Tasks 3/4/6).
- Malformed cross-session part linkage inside an excluded project: never return those bodies through a selected session (Tasks 2/3).
- Identical database/export text with different provenance: retain separate evidence identities and never promote export trust (Tasks 1/5/6).
- Two copies with one changed or privacy-excluded locator: verify and use a matching permitted copy only, without changing semantic metadata (Tasks 1/6).
- Scan stops mid-session and later continues: sealed parts retain ordinal/cache identities and unsealed text is neither lost nor prematurely summarized (Tasks 4/6).
