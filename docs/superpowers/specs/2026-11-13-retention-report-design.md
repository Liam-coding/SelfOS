# Knowledge retention report design

Issue #21: expose a bounded, read-only account of canonical knowledge and recent attempts. Reuse retention audits for category routing and consolidation, saved summaries for extraction, and existing diagnostics and operation journals for failures. Add metadata-only filtering and extraction outcomes where missing.

Use corrected canonical state; suppress examples for excluded sources. Current counts agree with the library. Stage totals have explicit units and scopes, rather than a subtractive funnel. An empty category never proves absence of eligible content. Legacy evidence, partial samples, pending jobs, malformed metadata and unresolved errors produce explicit uncertainty. Staging remains separate from canonical records.

Native Python and authenticated GET route; packaged responsive HTML/CSS/JavaScript with English-default i18n and Chinese parity. Reads are capped, never discover conversations or call models. Examples use reason codes, category/record identifiers and encoded local source links, never raw model responses, credentials or absolute paths.
