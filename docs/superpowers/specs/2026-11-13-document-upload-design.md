# Local document upload and knowledge organization (#11)

Status: proposed design, pending independent review and human approval. Documentation only.

## Intent and approaches

Provide a polished, keyboard-accessible picker/drop area for exported AI descriptions and summaries. Preserve original bytes locally before processing. Organize selected documents through the existing configurable knowledge pipeline with provenance, backups and recovery. Uploading never sends content to a model; the explicit Organize action does.

The implementer recommends one-file-at-a-time streamed binary admission plus a durable local registry. This bounds each request, simplifies cancelled-transfer cleanup and avoids multipart/base64 expansion. Multipart batch uploads offer a familiar wire format but require a bounded parser and compound partial-failure semantics; JSON/base64 uploads fit current JSON routes but inflate large requests and encourage whole-body buffering. Keep the existing Python server and packaged browser assets. These are implementer decisions for approval, not previously approved design choices.

Initial public formats: UTF-8/BOM `.txt` and `.md`, up to 20 MiB each. Empty or binary/non-UTF-8 files fail before admission. Initial JSON/JSONL support requires an explicitly registered structured-export adapter and is not assumed from a suffix. #12 can register the verified OpenCode export profile after its design/implementation passes; unknown JSON and PDF/DOCX are not advertised or guessed. No arbitrary JSON field traversal as personal facts.

## UI and workflow

Add an Upload documents entry next to existing source/import controls. Use shared tokens/controls and packaged assets, English default plus Chinese locale strings. A dialog contains:

```text
Upload documents
Drop .txt or .md files here
UTF-8, up to 20 MiB per file       [Choose files]
summary.md       Uploaded locally       [View original]
project.md       Already uploaded       [View original]
Selected: 2 files · Not sent to a model
Model: configured provider/model · Focus/detail: current settings
[Cancel upload]                    [Organize selected]
```

The picker is a normal labeled file input; the drop area is supplemental, not a fake button without keyboard behavior. Maximum 10 queued files, uploaded sequentially. Show independent queued/uploading/uploaded/duplicate/rejected/interrupted statuses, accessible live messages, byte progress when available, and actionable errors. Use XMLHttpRequest or equivalent browser API for per-file progress and abort. Filenames/errors render as text, never HTML. Closing the dialog does not cancel organizing; it remains visible in existing job progress. Cancel upload aborts the current transfer and queued transfers only. Completed admissions remain local. Responsive layouts, theme, reduced motion, focus return and locale switching preserve queue selection/status.

Show retained originals and paginated file history on reopening the dialog. Selected documents are explicit; Organize does not scan all local conversation roots or every retained upload. Unchanged processed documents show cached/no-new-work status rather than calling a model again. A retry is selected-source recovery, not a global rebuild.

## Admission, storage and HTTP boundary

Use the existing loopback/same-origin and authentication guards before reading file bodies, returning existing auth responses. The new upload route accepts a single raw `application/octet-stream` body, exact Content-Length 1..20 MiB, no transfer-encoding/chunked requests, and a bounded percent-encoded original-filename header. Browser File size and server Content-Length are independent checks. Reject multiple/conflicting length headers, missing/invalid length and incompatible content type. Bound header filename bytes, body read chunks, total bytes and transfer time; premature EOF/timeouts do not create ready entries. Close connections after rejected unread bodies so surplus bytes cannot become another request. Never call the generic unbounded `_read_body` helper for upload content.

Filename is display metadata only. Reject NUL/control characters, path separators, excessive length and unsupported suffix; never turn a supplied filename into a destination path. Internal paths use generated/content identities only. After auth/header validation, stream to a server-generated temporary file under `vault/.knowledge_uploads/incoming/`, compute SHA256 and validate UTF-8 with a bounded decoder. Resolve/contain all parent paths, reject symlink/junction escapes, never follow a caller-supplied path. Nonempty whitespace-only content may be admitted but is explicitly no eligible knowledge, not a fabricated fact.

Store immutable originals under `.knowledge_uploads/originals/<content-identity>.<normalized-suffix>`. Plain-text adapter canonicalizes txt/md to one storage suffix while retaining original format/name in registry metadata, allowing exact duplicate content across those extensions to reuse an original. IDs use SHA256 plus adapter profile; do not deduplicate incompatible parser profiles. Default originals and registry remain excluded from Git; `.knowledge_uploads/` is already ignored. Logs contain status/id/byte counts, not body text or credentials.

Admission transaction: stream/validate outside the short upload registry lock; acquire a dedicated upload lock; recover its journal; verify any duplicate original's bytes/hash; write an admission intent containing expected original identity and metadata; install the immutable original without overwriting differing existing bytes; atomically publish the registry entry; finalize the journal. Only registry-published entries are ready. Fsync content before publishing, with documented filesystem crash limits. Recovery completes a verified pending admission or removes only its owned incomplete staging entry; it never removes a different upload's original. Orphan completed originals without a recoverable intent are not automatically imported or deleted. Clean stale incoming files only after proving no live owner; never delete solely on age.

The registry is versioned/bounded and stores identity, profile, first upload timestamp, primary filename, bounded alias filenames, hash, byte count, immutable original path, content/provenance kind and retained/forgotten state. Atomic update helpers and dedicated recovery are needed: `storage.pipeline.safe_path` does not currently admit upload paths, so do not silently weaken its allowlist. Duplicate admissions reuse first timestamp/id and can add a bounded filename alias (max 8); do not reset processing progress. Registry pagination limits 1..100; file names/body content are not returned to unauthenticated clients. Registry corruption returns an actionable unavailable state, never automatic empty reset. Builder chooses a documented total-original storage cap and bounded registry sharding/indexing; storage exhaustion rejects a new admission before publishing it.

## Normalization and provenance

The admitted-document handoff is versioned and application-owned: immutable contained original, verified SHA256, original filename, first upload timestamp, stable admitted id, byte count and explicitly selected adapter profile. A model/request cannot supply its own locator/hash/provenance. Plain-text adapter first verifies/decodes the complete bounded original and applies the same full-text redaction as document_source, then fragments the resulting redacted text. Never redact chunks independently: secrets may cross transport/fragment boundaries. A 20 MiB raw cap permits bounded full-text normalization; enforce a documented parser memory/time cap and report indexing unavailable rather than falling back to unsafe chunk-local redaction.

Plain-text fragment identity includes admitted id, parser/redaction version, redacted-text character range and digest. These ranges refer to the fully redacted text, not raw byte or raw decoded-text offsets. Store that coordinate system/version explicitly. Source viewing reuses the same normalization version and digest before locating a fragment or paging it; unsupported old normalization returns unavailable/version feedback, never a false raw-text location. Strip/compact operations may change model excerpts but retained ranges always reference the pre-compaction redacted text. All fragments preserve original path/hash/name. Exact duplicate uploads produce the same fragments. No timestamps or author roles are inferred from prose. First upload time is labeled import time, never event time.

Plain AI documents use role=user as the existing pipeline envelope but provenance=quoted_dialogue, not user_statement or machine_summary. This preserves useful attributed project/experience/history content under current validation instead of suppressing the entire document. Existing personal fact/preference validation must not promote AI descriptions to verified facts. Runtime instructions/tool traces and transients still pass through existing content filtering. The file content is evidence and cannot grant tool permissions or override organizer instructions. Unknown authorship remains explicit; future self-authored source declarations are separate design work.

Use a neutral per-document project scope, namespaced by admitted identity unless a supported structured adapter has validated project metadata. Do not classify every upload as SelfOS or map a filename to an existing project silently. Initial UI has no project-context selector. Source/session project identity remains stable across reorganization; model-generated project descriptions are evidence-derived content, not permission to rewrite source identity. A future explicit project-context association needs its own identity/privacy/cache design rather than changing the stored source project in place.

Evidence matching uses the redacted original/fragment text as existing validators expect. Store parser version and fragment ranges/digest in application source metadata and preserve them through cache/staging/canonical writes. Original viewing verifies original hash and returns existing redacted pagination plus an optional supported-fragment locator. Do not assert arbitrary serialized JSON offsets prove a quotation: structured adapters own locator mapping. Existing `document_source` containment/hash/encoding/size checks and PR70 metadata safeguards remain active.

## Organization, state and recovery

Organize selected validates registry ids and original hashes, constructs bounded normalized inputs, and invokes the existing knowledge job manager/run_knowledge with selected messages/sessions. Use the same active-run lock as manual local imports, restores and scheduled work; two starts cannot create two organizers. Upload receipt is not a saved summary or committed knowledge.

Before starting, build a bounded local document-processing preview (not a model call): explicit selected IDs, eligible compact parts, policy/settings identity and request allowance. Reuse existing sample-sized limits initially; show partial coverage and Process more. A 20 MiB admitted file is not permission to send 20 MiB to a model. Stable continuation operates on persisted normalized document input with deterministic full-file fragment/part identities: never hand the next subset to prepare_sessions starting at part 0 and overwrite an earlier summary. Stream/index the document once under a bounded local time/input budget; persist the fragment inventory and sealed compact parts atomically with its cursor. Last unsealed part carries until finalized. If local index limits are reached, show indexing pending and resume locally, without summarizing an unstable tail. No full personal-history scan.

Processing fingerprint includes original/profile, stable source scope, retention policy, fragment/part identity and privacy revision. Reuse existing request allowance, retries, stop flag, checkpoint, corrections, summarizer/refiner, selected-part coverage and transactional canonical installation. Do not build a second classifier/store. Privacy is checked before extracted data/model dispatch/refinement/publication and source viewing, with selected registry originals excluded by existing rules. Settings/privacy changes invalidate a stale preview and require local rebuilding; previously saved progress is preserved.

Registry tracks admission/retention, not authoritative knowledge completion. A per-document processing receipt records selected part identities and their committed canonical operation/checkpoint after publication. Because existing RunJournal may fail noncanonically, never mark completed solely from its display status. Derive/reconcile processing receipts from committed state/manifest evidence on restart. Canonical restores invalidate receipts whose published parts no longer exist; they show needs organization rather than cached success. A crashed run after publication but before registry display update is reconciled without another model call. Define durable receipt/index writes through the shared transaction boundary rather than best-effort post-publication writes; extend its explicit validated path set for owned upload-processing metadata only, with restore/migration coverage.

Expose ready, indexing, pending organization, processing, saved checkpoint, committed, failed, stopped and original unavailable distinctly. Existing job controls handle stop/resume/retry and auth expiry; do not autostart after restart. Partial processing shows processed/remaining part counts and source-specific continuation. #16 can later consume these same statuses; #17 can link future change receipts without changing storage ownership here.

## Retained originals and portability

View original is always available for a valid retained source. Forget from upload queue removes its ready selection, not knowledge or physical original. Show that referenced originals are retained to preserve evidence. Explicit deletion of originals is deferred; never silently remove them on failed processing/duplicate uploads. An original externally deleted/changed reports unavailable/changed. Re-uploading bytes matching its registered hash/profile may repair that identity; mismatching input produces another content identity, never a replacement.

Missing original repair installs the verified bytes through admission. Changed original repair first validates the existing path is an owned regular contained file with no symlink/junction escape, then records a repair intent under the registry lock and moves the changed original to a collision-safe `.knowledge_uploads/quarantine/` path. Preserve that file and repair metadata; never delete/overwrite the changed bytes. Install verified registered bytes only after the quarantine move, atomically complete the ready registry state, then finalize the repair journal. Recovery recognizes and completes each intended stage by expected file/hash identities or reports unavailable without guessing. Quarantine counts against storage limits; if it cannot be safely preserved, reject repair. A damaged original without a matching registry entry is a collision/error, not permission to repair an arbitrary file. Concurrent upload repair and processing use a consistent immutable snapshot; in-flight validation aborts on changed input and resumes only after explicit restart.

Integrate with migration: originals remain opt-in as today; bundles without originals retain traceable metadata and clearly unavailable status. Validate admitted registries/profiles/hashes/ranges and paths before install, reject conflicting existing identities, and restore upload-processing receipts with canonical state. Bundled filename/path cannot write outside the originals directory or grant new local-source permissions. Backups preserve knowledge processing metadata and source references; immutable originals are retained separately instead of repeatedly copying them into every knowledge backup.

## Acceptance and implementation boundaries

Synthetic and loopback only: authenticated picker/drop upload; button keyboard path; dark/light mobile locale; partial transfer/cancel/restart; no model calls on admission/preview; sequential batch behavior; mismatched/duplicate length and size/time caps; traversal/control filename and symlink escapes; raw-byte/BOM/hash preservation; concurrent same-hash admissions; crash at each admission stage; corrupt registry; duplicate alias cap; text/Markdown parsing and whitespace-only file; provenance cannot establish user facts/preferences; selected-only organization with no local scan; policy/detail focus, ignored transients, correction suppression; stable partial indexing/part continuation; source quotes/hash/ranges after cache replay; privacy changes; stop/resume/auth expiry; canonical commit/restore receipt reconciliation; opted-in/out migration originals. Run full regression and isolated browser flow after implementation; existing registered-document tests alone are insufficient.

Deliver complete #11 from upload UI through committed knowledge and usable original links, with documented formats/privacy/storage/cancel behavior. Text/Markdown are the initial supported formats, not an excuse to omit provenance, selected processing, original lifecycle or recovery. JSON OpenCode registration is a dependent #12 delivery, not a claim of generic JSON support. Modules, exact route names, bounded disk defaults and index serialization are implementer choices constrained by this document.
