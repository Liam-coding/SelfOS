# Durable knowledge corrections design

User intent: edit, delete and merge browser records without changing original source conversations, and prevent rebuild/import from recreating manually removed errors.

Implementation decision: keep a versioned correction ledger in vault/.knowledge_corrections.json, separate from generated .knowledge_pipeline.json. Canonical generated state remains source evidence; a pure overlay creates corrected views and managed exports. The atomic pipeline transaction writes both the ledger and affected managed files. Existing backup/recovery protects the whole action.

Identity: browser display IDs are content versions and used for optimistic concurrency; correction anchors are category + relation + scope + source evidence signatures. Lesson/history anchors use normalized source-supported text and source signatures; project anchors use project identity. An edit carries the original generated snapshot and explicit manual fields, never rewrites its quotation. Deletes suppress the matching claim from unchanged source material. New evidence for the same relation can remain a proposed conflict; it cannot silently replace a correction. Suppression targets the deleted claim and original evidence, not an entire project or every future value.

Operations: authenticated/local edit, delete, merge and undo API. Editing permits display text and personal fact/preference value, leaving source evidence separate and clearly labelled as original evidence. Merging requires compatible category/relation/scope for personal facts/preferences; lessons/history require same category; projects are not merged through knowledge correction (project aliases already implement their separate identity operation). The result retains all source links and original generated versions. Project editing changes summary intent only; structured status and timeline remain generated. Delete can hide a project view but does not delete its source sessions or underlying project history.

Ledger entries have action ID, UTC user-action time, target version/anchors, originals, patch/result and active/undone status. Undo deactivates one action, recomputes the overlay from present generated state and remaining actions, and creates a new backup. It does not restore an entire old vault over later imports. Unknown/stale IDs return a conflict before writing. Repeated actions are idempotent by action ID. User text is size limited, redacted and rendered through DOM textContent, never treated as model evidence or HTML.

UI: localized actions in record details, keyboard-labelled edit inputs, delete confirmation with clear scope, merge selection restricted to compatible records, and recent actions with undo. Show manual correction badges, original quotations, source navigation and later conflicting evidence. Keep default English and Chinese catalogs.

Integration: apply overlay to browser list/count/details, agent context, managed Markdown and cache/refinement context. Centralize its application so rebuild and incremental import both respect the ledger. Do not silently replace canonical generated snapshots with corrected output. Block mutations while an import is active; use the existing vault lock and atomic journal. Tests use temporary vaults, synthetic evidence and mock HTTP, never real model requests.

Verification: pure replay/edit/delete/merge/undo tests, repeated imports and cache rebuild, later conflicting sources, optimistic-concurrency rejection, atomic-write failure and recovery, provenance invariants, authentication/local origin restrictions, English/Chinese Chromium and keyboard checks.

Open implementation choices are assigned to the builder within the approved issue scope. Live-model quality evaluation for #38 remains a separate pending authorization, and does not block designing this deterministic correction capability.

Resolved design rules (builder decisions):
- Suppression anchors include original category and exact supporting source/quotation signatures. When identical old evidence is re-extracted with changed keys or wording, it is quarantined as a possible suppressed lineage rather than reintroduced as active knowledge. Matching a selected record never suppresses an entire source file. If a generated aggregate mixes old and genuinely new supporting evidence, retain the new observations as a visibly conflicting candidate and preserve old support in the action history. Related claims sharing a quotation may need review rather than silent discard. This favors prevention of known errors over automatic reclassification.
- Undo of an action with active dependent edits/merges is rejected with dependency information. Users undo dependents first; no cascade silently discards later edits. Undo is local overlay replay against current generated state, not whole-vault time travel.
- A manual correction is sticky for its relation and scope until explicitly undone/replaced. Future and new-source candidates remain visible conflicts; scheduled generated changes cannot silently take over a manual correction. Corrections retain the original source snapshot but do not claim its quote supports the edited content.
